# test-driven-development

**Para quê:** TDD estrito: escreve o teste, **vê falhar**, escreve o mínimo para passar, refatora. Código escrito antes do teste é descartado.

**Quando usar:**
- Qualquer feature ou correção de bug em projeto pessoal.
- Lógica de negócio, cálculos, regras.

**Quando não usar:**
- Protótipo descartável, spike exploratório, ajuste visual.

**Como acionar:** "faz com TDD". Ou pelo nome: `/test-driven-development`.

**Atenção:** Bem rígida de propósito. Nas rédeas globais, a regra é mais leve ("comportamento novo vem com teste").
